# Website in five languages — plan

Status: **built on branch `site-i18n` in both repos (2026-10-13)** — phases 2–5
done; translations reviewed by the owner (no changes); preview deployed and
verified (step 18). Owner test (step 19), merge and phase 7 remain. See "As built" at the end.

Goal: every page of https://stackdplatform.com in the app's five languages
(en, fr, it, es, pt), with a language menu on every page and an automatic
pick of the visitor's language on arrival.

The site lives in the separate StackdSite repo (static HTML on Cloudflare
Pages, no build step, no JavaScript); its generators live in this repo under
`tools/site/`. See `tools/site/README.md` and the site's own `README.md`.

## Where we start

- `/privacy` and `/terms` are hand-written English; `/fr|it|es|pt/{privacy,terms}`
  are generated by `tools/site/legal.cjs` from `src/i18n/*.js`, with hreflang
  alternates and an "Other languages:" line.
- Home (`index.html`, ~1,030 words) and Support (`support.html`, ~1,320 words)
  are English only, so translated legal pages link back to English pages.
- The CSP in `_headers` is `script-src 'none'`: the site runs no JavaScript.
  The menu must be plain HTML and the language pick must run at the edge.
- 7 of Support's 17 FAQ entries exist in the app's dictionaries (`faq.*`) but
  have drifted from the site's text; the site keeps its own copy.

## Decisions

| # | Decision | Answer |
|---|---|---|
| D1 | Remember the chosen language in a cookie? | **No.** Redirect only visitors arriving from outside the site; internal navigation never redirects. Keeps "this website sets no cookies" true. Trade-off: someone who prefers English on a non-English browser picks English once per visit. |
| D2 | Which pages redirect? | **All four English root pages:** `/`, `/support`, `/privacy`, `/terms`. |
| D3 | Who reviews translations? | **The owner reviews all four languages.** |
| D4 | Translated screenshots? | **Now**, as part of this work. |
| D5 | Signal for the language pick | Browser language (`Accept-Language`), never geo-IP (wrong for CH/BE/CA, expats, VPNs). |
| D6 | Mention the redirect on the privacy page? | **Yes**, one sentence in the site-only "This website" clause, all five languages. The page's "Last updated" date comes from the app's `terms.updatedDate`, so it moves only with an app release. |
| D7 | Translate the Open Graph image? | **No.** Translated pages reuse `img/og.png`. Its "never leaves your phone / No cloud / 0 servers" is accurate while Bank Connect is unreleased; revisit `tools/site/og.html` when Bank Connect launches. |
| D8 | URL layout | English at the root (store-listing URLs unchanged); others under `/fr/`, `/it/`, `/es/`, `/pt/` with English slugs (`/it/support`), as the legal pages already do. |

## Phase 5 — Automatic language redirect (assistant)

| # | Step |
|---|---|
| 13 | `functions/_middleware.js` + `_routes.json` in StackdSite, routes limited to `/`, `/support`, `/privacy`, `/terms`. Rules: GET/HEAD only; if the `Referer` origin equals the request's own origin, serve as is; otherwise choose the best of en/fr/it/es/pt from `Accept-Language` by q-weight (regional tags map to the base: pt-BR → pt, fr-CH → fr; `*` ignored); if that is not en, `302` to `/<lang><path>` with `Cache-Control: no-store` and `Vary: Accept-Language, Referer`; else serve English. Crawlers send no `Accept-Language`, so they get English and find the rest via hreflang. |
| 14 | The function sets the site's security headers itself (CSP, nosniff, X-Frame-Options, Referrer-Policy, Permissions-Policy) on both redirects and pass-through responses: Cloudflare documents that `_headers` rules do not apply to Function responses. |
| 15 | Test script in `tools/site/` for the picking rules: weights, regional variants, wildcard, missing header, same-origin referer, crawler. |
| 16 | D6: the privacy sentence in `legal.cjs`'s `UI.*.website.d` (fr/it/es/pt) and in the hand-written English `privacy.html`. |

Wrangler's upload skips `functions/` and `_routes.json` (`IGNORE_LIST` in

a static file — still verified on the preview (step 18), given this repo's
history with stray published tools.

## As built (2026-10-13)

- **Generator:** `tools/site/pages.cjs` + `layout.cjs` + `strings/<lang>.cjs`
  (159 strings per language). English root pages are generated too.
  `legal.cjs` now uses the shared layout and also rewrites the `<header>` and
  `<footer>` blocks of the hand-written English `privacy.html`/`terms.html`.
  Checks: same keys/list lengths/placeholders/`<b>` count as English, no long
  string left in English (allowlist: `home.title`, `brandLabel`), every
  root-relative link and image exists; `legal.cjs` also checks the English
  website clause equals `legal.website.d`.
- **Links are root-absolute** (`/fr/support`, `/styles.css`) so one template
  works at any depth, including the 404 pages.
- **Menu:** `<details class="lang">` inside `.nav`; the phone rule became
  `.nav > a:not(.btn)` so the menu's own links are not hidden. Current
  language marked `aria-current` with a ✓.
- **Screenshots:** 4 per language (home dark/light, history dark, debt dark),
  English recaptured too. `tools/seed.cjs` takes an optional `loc`
  (account names, notes); store screenshots are unchanged. Default category
  names stay English in every language — the app's own i18n decision 3.
  Alt text carries the figures exactly as each language's screen shows them
  (the app prints `€` first in every locale and `4.05%` with a point).
- **Redirect:** `StackdSite/functions/_middleware.js` + `_routes.json`;
  `tools/site/redirect-check.cjs` (35 checks) covers the language pick,
  referer rule, untouched routes, response headers and parity with `_headers`.
- **Privacy (D6):** sentence added to "This website" in all five languages.
- **Runbook:** `docs/broker-runbook.md` §6 now points at `support.status` in
  the string tables.
- **Review aid:** `tools/site/review-sheet.cjs` writes a side-by-side HTML
  table of every string.
- **Preview verified (step 18, 2026-10-13, `site-i18n.stackd-site.pages.dev`):**
  302 to `/<lang>/…` for it, fr-CH, es, pt-BR on all four root pages; 200
  for English, German-then-English and no `Accept-Language`; same-origin
  Referer → 200, external Referer → 302. `/functions/_middleware.js` and
  `/_routes.json` → 404. Security headers present exactly once on the
  function routes, the redirect (with `Cache-Control: no-store`) and static
  pages. `/it/nope` serves the Italian 404. One pt-BR `/support` request
  returned 404 during the rollout and did not reproduce on three retries.
