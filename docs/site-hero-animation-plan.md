# Site hero title animation — plan

Status: **approved 2026-10-17** with the recommended decisions (D1 A, D2 as
proposed, D3 A, D4 videos after the site ships). **P1 built and the motion
approved** (§10). P2 in progress.

Goal: animate the home page title ("Money tracking that stays on your phone."
and its four translations) on stackdplatform.com, starting from **one HTML
scene that draws the title at time t**, rendered frame by frame by a headless
browser. It must run smoothly in all five languages and on every device size.

## 1. What the site allows today (findings)

| Fact | Consequence |
|---|---|
| `_headers` CSP has `script-src 'none'` — the site runs no JavaScript at all | On the live site the animation must be **pure CSS** (or a video). Only the offline renderer may run script. |
| Pages are generated by `tools/site/pages.cjs` from `tools/site/strings/<lang>.cjs` | The title markup (word spans, accent) is produced by the generator, never hand-edited. |
| `.hero h1` is `clamp(38px, 5.6vw, 66px)`, Manrope 800, `text-wrap: balance`; `.hero h1 em` (accent colour) exists but is unused | Motion must scale with the font size (use `em`), keep the balanced line breaks, and the accent hook is ready. |
| Manrope is `font-display: swap` and **not preloaded** | A late font swap would reflow the words mid-animation. Needs a preload + metric-matched fallback. |
| All five titles use only Latin-1 letters (é, ó) — covered by `fonts/manrope-latin.woff2` (24 KB) | Preloading that one file is enough for every language. |
| **On phones the title is below the fold.** Measured (Chromium, all 5 languages): the phone screenshot comes first under 860 px, so the title starts at y ≈ 831 px — partly visible on 390×844, below the fold on 360×780 and 320×640. On tablets and desktops it is in view (y 184–267 px at ≥ 1024 wide). | A load-time animation would finish before most phone visitors scroll to it — decision D3. |
| Title length: en 7 words, fr 6, it 7, **es 9**, pt 7; 2–3 lines on phones (fr: 4 lines at 320 px), 2–3 lines on desktop | The reveal must take the same total time whatever the word count. |
| No full `ffmpeg` on this machine; Playwright 1.63 ships only Chromium (`chromium-1243`) and a VP8-only recorder ffmpeg | Frames and contact sheets need nothing new. MP4 export needs ffmpeg; WebKit/Firefox checks need `npx playwright install webkit firefox`. Both are installs — ask first. |

## 2. Approach: one scene, two outputs

The title's motion is written **once**, as CSS `@keyframes` in the site's
`styles.css`, on word spans the generator emits.

1. **The live site** plays those keyframes in the visitor's browser — real,
   selectable, indexable text, crisp at any pixel density, re-wrapping to any
   screen width, about 1 KB of CSS, no script (the CSP stays as it is).
2. **The scene** (`tools/site/hero-scene.html`) loads the same `styles.css`
   and fonts and draws the same title on a canvas of a given format. A
   renderer pauses every animation and **seeks it to exactly t**, so the page
   becomes a pure function `frame = f(lang, format, theme, t)`. The headless
   browser screenshots each t. The renderer can also seek the **real site
   page** the same way, which is how every language × device is proven
   before it ships.

The frames give: contact sheets for review, automated checks (§6), and — if
wanted — MP4 videos for social posts and the store listings (D4).

## 3. The timeline — t defined from industry standards

| Parameter | Value | Source |
|---|---|---|
| Frame rate | **60 fps** master (frame n ↔ t = n / 60 s); a 30 fps export takes every 2nd frame | 60 Hz is the standard display refresh for UI motion; 30 fps is the social-video floor |
| Start delay | **0.10 s** | ≤ 100 ms reads as instant (Nielsen response-time limits) |
| Word entrance | **0.50 s** each: opacity 0 → 1, `translateY(0.4em)` → 0 | Material 3 duration token *long2* (500 ms) for large elements entering; 0.4em scales with the clamp() font size |
| Word easing | `cubic-bezier(0.05, 0.7, 0.1, 1)` | Material 3 *emphasized decelerate* (entering elements). No bounce or overshoot — calm, trustworthy for a finance brand |
| Stagger | `s = clamp(40 ms, 480 ms / (n − 1), 80 ms)` | 40–80 ms per item is the common list-stagger range; the formula fixes the window, so es (9 words) ends when fr (6) does |
| Accent | **1.10 → 1.50 s**: the accent phrase turns accent colour and an underline draws left → right, easing `cubic-bezier(0.2, 0, 0, 1)`, 0.40 s | Material 3 *medium4* (400 ms) + *standard* easing |
| Rest state | **t = 1.50 s** — identical to the static title (accent phrase in accent colour, underlined), which reduced motion shows at once | Plays once, never loops: under WCAG 2.2 SC 2.2.2's 5 s limit, so no pause control is needed |
| Reduced motion | `prefers-reduced-motion: reduce` → no animation, the rest state at once | WCAG 2.3.3 / platform setting honoured |
| Flashing | none | WCAG 2.3.1 |
| Video length | **4.0 s** (1.5 s reveal + 2.5 s hold = 240 frames) | 3–5 s title card; enough to read the 9-word Spanish line |
| Video frames | 1920×1080 (16:9), 1080×1920 (9:16), 1080×1080 (1:1); text inside the 90 % title-safe area | Platform-standard social sizes; SMPTE ST 2046-1 safe areas |

The word timeline, with the stagger formula applied:

```
t (s)   0.0   0.1        0.58      1.08 1.10        1.50              4.0
        |hold |-- words rise, staggered --| |accent draws| rest (video holds)
en  7 words: s = 80 ms → last word 0.58–1.08
fr  6 words: s = 80 ms → last word 0.50–1.00
es  9 words: s = 60 ms → last word 0.58–1.08
```

The brand idea: the words rise and settle into place, one on another —
*stacking* — then the privacy promise is underlined.

## 4. Determinism contract (why every render comes out identical)

1. **The scene never reads a clock.** Motion is declared in CSS only; the
   renderer calls `document.getAnimations()`, pauses each one and sets
   `currentTime = t × 1000`. No `requestAnimationFrame`, `Date`,
   `performance.now`, `Math.random` or transitions anywhere.
2. **Time is exact:** t = n / 60 from an integer n — no float accumulation.
3. **Ready before frame 0:** `document.fonts.ready`, every image decoded, and
   `document.fonts.check('800 1em Manrope')` must pass — the renderer fails
   instead of saving a fallback-font frame.
4. **Fixed environment:** viewport, deviceScaleFactor, colour scheme,
   `reducedMotion: 'no-preference'`, locale; Chromium pinned by Playwright
   (`chromium-1243`); software rasterisation and an sRGB colour profile.
5. **Screenshots with `animations: 'allow'`** (Playwright's `'disabled'`
   fast-forwards animations to their end) and `caret: 'hide'`.
6. **Never Playwright's `recordVideo`** — it captures in real time and drops
   or duplicates frames.
7. **Proof:** `--verify` renders twice and compares a SHA-256 per frame.
8. Encoding with fixed x264 settings is deterministic as well.

Limit: frames are byte-identical **on this machine with this Chromium**.
Another OS, GPU or Chromium build can differ in anti-aliasing, so videos are
always rendered here. Visitors' devices play the live CSS: the same timing and
curves, not the same pixels.

## 5. All five languages

- **Split by word at generation time**, with `Intl.Segmenter(lang, { granularity: 'word' })`;
  punctuation stays on its word (`comptes,` `téléphone.`). Never per letter:
  that breaks Manrope's kerning and makes screen readers spell.
- **Accessibility:** `<h1 aria-label="…full sentence…">` with the word spans
  `aria-hidden`, so a screen reader hears one heading in every language and
  the text stays in the page for search engines. Checked through the
  accessibility tree in all five languages.
- **Fixed reveal window** whatever the word count (stagger formula, §3).
- **Accent phrase marked with `<em>` per language** in `strings/<lang>.cjs`
  (D2). The underline is the `<em>`'s own background, so it runs on across a
  line break inside the phrase (§10).
- **Glyph check:** the generator fails if a title has a character outside the
  preloaded font file's range.
- **Line breaks unchanged:** words are `inline-block`, `text-wrap: balance`
  stays; the renderer checks each language's breaks match the static page at
  every width.

## 6. All devices

- **Only `transform` and `opacity` move the words**, so the motion runs on the
  compositor thread and stays smooth on low-end Android even when the main
  thread is busy. The accent (colour + underline) is painted, on 2–4 words for
  0.4 s (§10).
- **No layout shift:** each word holds its final box from frame 0 and is
  hidden by opacity only — CLS 0.
- **Progressive:** the hidden state exists only inside the animation
  (`animation-fill-mode: both`); without CSS or animation support the title is
  simply there. No `opacity: 0` in the base styles.
- **Fonts:** preload `manrope-latin.woff2`, plus a metric-matched fallback face
  (`size-adjust`, `ascent-override` on local Arial) so a late swap cannot move
  words mid-reveal.
- **Test matrix:** widths 320, 360, 390, 412, 768, 1024, 1280, 1440, 1920 ×
  DPR 1/2/3 × light/dark × 5 languages in Chromium; WebKit and Firefox through
  Playwright; Chrome on the Android emulator; the owner's phones for real iOS
  Safari and Android, on the branch preview.
- **Automated checks on the real pages:** the last frame equals the
  reduced-motion render pixel for pixel (the animation lands exactly on the
  design); same line breaks in frame 0 and the last frame; no horizontal
  overflow at 320 px; one heading with the full sentence in the accessibility
  tree.
- **Performance:** DevTools trace at 4× CPU throttle — no layout per frame,
  ≥ 58 fps; Lighthouse mobile — CLS 0, LCP within +100 ms of today.

## 9. Decisions for the owner

- **D1 — What visitors get.** **(A, recommended)** the live CSS animation of
  the real text, from the same keyframes as the scene; the frames are for proof
  and videos. (B) the rendered video in the hero: 5 languages × several
  layouts of video files, fixed line breaks that cannot follow the screen
  width, text that is no longer real text, blocked autoplay in iOS Low Power
  Mode, and a CSP change (`media-src`).
- **D2 — Accent phrase per language** (owner reviews the wording):
  en *stays on your phone* · fr *sur votre téléphone* · it *sul tuo telefono* ·
  es *sin salir de tu teléfono* · pt *no seu telemóvel*.
- **D3 — Phones.** **(A, recommended)** under 860 px, show the eyebrow and
  title above the screenshot (lede, buttons and facts stay below it): the title
  lands near the top of every phone and the promise is the first thing read.
  (B) keep the layout and reveal on scroll with `animation-timeline: view()` —
  Chrome/Android and Safari 26+, static in Firefox, scrubbed by the scroll so it
  can rest half-revealed. (C) keep the layout — on most phones the reveal plays
  unseen.
- **D4 — Videos.** **(Recommended)** MP4s in 16:9 and 9:16 for the five
  languages after the site ships; needs a full ffmpeg (`winget install Gyan.FFmpeg`,
  asked before installing). Or skip for now — P1 still produces the frames.

## 10. As built — P1 (2026-10-17)

Files: `tools/site/hero.cjs` (word splitter), `hero-motion.css` (the
motion, moves into `styles.css` in P2), `hero-scene.html` (the scene),
`hero-render.cjs` (renderer), the five `strings/<lang>.cjs` titles with
their `<em>`, `tools/site/out/` in `.gitignore`, README section. The site
repo is untouched: `--site` swaps the new title markup into the home pages
on the fly until P2 generates it.

Measured: 9 animations in en/it/pt (7 words + the period + the accent), 8 in
fr, 11 in es; the rest state is at **1.50 s in every language** (end time read
from the CSS by the renderer, not hard-coded).

Changes from the plan, found while building:

- **Underline = the `<em>`'s background, animated by `background-size`**,
  not a `scaleX` bar per word. Per-word bars leave gaps at every space, and
  an inline-block word cannot share one `text-decoration`. An inline
  element's background (`box-decoration-break: slice`, the default) runs
  continuously across spaces and on to the next line, as the 9:16 frames show
  ("stays on" / "your phone"). It is painted, not composited, on 2–4 words for
  0.4 s. A 0.07em bottom padding drops it clear of the descenders (vertical
  padding on an inline box does not move the lines).
- **Trailing punctuation** after the `</em>` ("phone</em>.") gets its own
  span with its word's `--i`, glued by a WORD JOINER (U+2060), so it rises
  with the word, stays out of the accent and never wraps alone.
- **Words split on spaces**, not `Intl.Segmenter`: the same result for these
  five languages, with less code.
- **Two determinism traps `--verify` caught and the renderer now closes:**
  1. *Subpixel text.* Chromium turns LCD anti-aliasing off wherever layers are
     composited, so the reduced-motion render (LCD) never matched the animated
     last frame (grayscale). Rendering with `--disable-lcd-text` fixes it, and
     LCD fringes are wrong in a video anyway.
  2. *Wall-clock head start.* Animations ran in real time from page load until
     the renderer paused them; under CPU load that gap grew long enough for
     Chromium to put a word on a compositor layer, drawn slightly
     differently. Frames 7–66 of one variant (fr 9:16) and 60 frames of
     another (it) differed between runs, only when the machine was busy.
     Rendered pages are now requested with `?render`, which adds a
     stylesheet holding every animation paused from the first style pass.
- **Preview video without installing anything:** `--preview` uses
  Playwright's bundled VP8-only ffmpeg when no full one is found. P4 still
  needs a full ffmpeg for H.264.
